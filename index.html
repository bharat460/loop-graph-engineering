Loop Engineering

You used to hold the tool. Now you design the thing that holds it.

For about two years, a coding agent meant this: you type, you wait, you type again. You were in the chair for every turn. That part is ending. You still set the destination. You stop driving each mile.

Prompting

You, every turn

  1. Fix login. It’s broken.
  2. I changed the API. Try now?
  3. No — don’t touch the API.
  4. Okay, reverting. What next?

You hold the agent. If you walk away, the work stops.

Loop engineering

A recipe on the wall

  • Goal Login works on phone and desktop.
  • Rules Don’t change the API.
  • Done when Tests pass. Lint is clean.
  • Ask first Anything risky — delete, push, force.

The loop holds the agent. You wrote the recipe once.

What you write instead

A loop is a recursive goal: purpose in, iterate until it’s actually done.

Think of it as a recipe, not a chat. You name the destination, the house rules, how you’ll know you’re finished, and when the agent must tap you on the shoulder. Then you leave it in YOLO for safe work — tests, lint, reads — and it still asks before anything that can hurt.

loop.spec YOLO · safe runs, risky asks

Good to have in a loop

The spec starts it. These keep it from leaking.

Goal, rules, acceptance, YOLO, and decisions.md are enough to run. These three are optional extras — until the loop has to remember, plug into your tools, or stop guessing your project.

  • So it doesn’t re-guess the project

    Skills

    Conventions and “never do this” live outside the chat. Every turn loads them. Without this, the loop re-derives your repo from zero.

  • So it can act, not only edit files

    Connectors

    GitHub, Linear, Slack. A loop that only sees disk can only propose. A connected loop opens the PR and updates the ticket.

  • So the next turn has a memory

    State

    decisions.md is the loop’s disk. The model forgets between turns. The file doesn’t. Tomorrow’s run reads yesterday’s choices.

Side by side

Same bug. Two ways to ask.

A normal prompt is a nudge. A loop prompt is a contract: goal, rules, done-when, YOLO, and a notebook. Same login bug. Completely different day.

Fix the login page. It’s broken.

What happens: it guesses. It might change the API. It might skip tests. You stay in the chair and steer every turn. Walk away and it stops.

  All tests in test/auth pass.
  Lint is clean.

YOLO

  Verifier grades. Implementer does not grade itself.

What happens: it keeps going until the checks are true. Safe commands run. Risky ones wait for you. Tomorrow’s run reads decisions.md instead of asking you to re-explain.

Graph Engineering

A loop is one worker. A graph is an office.

The agent swarm is just org design: a lead, a researcher, a senior, and QA, with reporting lines. Work walks the floor the way it would in a real team. The lead does not write the code. The writer does not sign it off.

The floor

Click a seat, or send a ticket.

Lead assigns. Researcher explains. Senior builds at a separate desk. QA grades. The lines between them are the graph — not decoration, the actual reporting structure.

The part that does not automate

Build the loop.
Keep your engineer alive.

The loop changes the work. It does not delete you from it. Two people can ship the same loop and get opposite results: one uses it to move faster on work they understand. The other uses it to avoid understanding. The loop does not know the difference. You do.

  • Verification stays yours

    An unattended loop also makes unattended mistakes. “Done” is a claim. Your job is still to ship code you confirmed works.

  • Understanding can rot

    The faster it ships code you did not write, the bigger the gap between the product and what you actually get. Read what the loop made.

  • Comfort is the trap

    When it runs itself, it is easy to stop having an opinion. Designing the loop with judgement is the cure. Designing it to avoid thinking is the same action, opposite result.

Write the goal. Write the rules. Write decisions.md. Staff the office. Then keep the only job the graph cannot take — being the engineer who still cares what ships.
